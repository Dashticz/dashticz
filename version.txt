Split the single --icon-image-size variable into two independent ones - --icon-font-size (the FontAwesome icon column, .col-icon .icon) and --icon-image-size (actual img icons) - since a device's custom image and a widget's FontAwesome icon are unrelated and were previously forced to the same size; the Icon size section now shows an Icon row and an Image row. Widened the active custom stylesheet notice next to the Path/URL field - it was sizing to its own content by default, wrapping its text across 4 short lines; it now has a 260px minimum width and grows to fill the row, wrapping across 2 lines instead. Fixed CONFIG.js accumulating growing runs of blank lines between editor-managed sections (screens, grid layouts, widgets) every time one was resaved. configwriter_remove_section() spliced the raw text before the removed section straight onto the raw text after it, but both sides already carried their own leading blank line from configwriter_wrap_section() - so every removal (which happens on every save, since a section is always removed and re-appended) stacked another blank line onto the same spot, compounding without bound over repeated saves. It now trims the whitespace on both sides of the cut and rejoins with exactly one blank line. Also fixed configwriter_upsert_root_config_settings() (config[\"key\"] = value; settings written by the Settings UI) always deleting and re-appending a changed key at the end of the config block, scattering it away from the related settings it was originally grouped near - an existing single-line setting is now updated in place instead, only genuinely new keys get appended. Bootstrap's .btn-group is an inline-flex element, so it inherited its position from .mh's text-align: right (used to right-align plain value text elsewhere in the same block); the button group now gets its own display: flex; justify-content: center; width: 100%, unaffected by that text-align. Vertically centered a Selector Switch's option buttons/dropdown below the title, and gave the SelectorStyle 1 dropdown (e.g. Husqvarna, Lyrion) the same full-width treatment the buttons already got. .col-data is now a flex column - scoped with :has(.selector-buttons)/:has(> select) so every other block's plain title/value/lastupdate stacking is untouched - with the button group or select centered in the remaining space via auto margins. But _init()/_prepareManagedDeviceState() unconditionally rebuilt every device's in-memory state from blocks[]/columns[] on every popup open - and those client-side globals are never patched after a save, only the server's CONFIG.js is - so the second edit's save resent the first device using its stale pre-edit data, reverting it server-side. Reproduced directly via saveblocks.php's actual request payloads (second request's first device reverted to its original title) and fixed: openLayoutConfig() now preserves already-known device/special state across repeated calls in the same session instead of re-deriving it from the stale client-side globals; verified the same reproduction now correctly resends both devices' edited titles. Fixed finger-swipe screen navigation silently doing nothing on narrow (phone-width) touch devices when the 'Enable Swiper' setting was set to 1. With Swiper never created, screenswitcher.js's non-swiper goToScreen() fallback only show()/hide()s the active screen and has no gesture handling at all, so a finger swipe had nothing listening for it. Flipped the condition to match the documented behavior. Fixed touch-swipe screen navigation not working at all on at least one real Android tablet, even with 'Enable Swiper' left on its default value - the screen-switcher buttons and mouse drag both still worked there, isolating it to something Swiper-specific. Swiper was being loaded via a lazy import() chunk (window.loadSwiper() in src/index.js), separate from the main dist/bundle.js - on that tablet, fetching that separate chunk at runtime silently failed, so myswiper never got created and no touch handler was ever listening for a swipe (confirmed by comparing against the master branch, which bundles Swiper directly and doesn't have this problem).
